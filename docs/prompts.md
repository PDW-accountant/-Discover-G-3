### [10/4] 문희원 출발역 검색·참여자 관리 — "앞뒤 기능의 입력·출력 형태를 그대로" (#3, #4)
- 상황: 출발역 검색 함수(`searchStations`)와 출발지 입력 화면을 맡았다. 같은 함수를 대원님의 참여자 직접 입력 화면(`join.js`)이 이미 부르고 있었고, 다음 단계(순위 계산 `recommend.js`, 공유 링크 `share-link.js`, 서버 저장)도 참여자 형태를 정해 둔 상태였다.
- 초안 프롬프트: "#2 이슈에 대한 코드 생성 작업을 진행할거야."
- 결과 / 문제: AI가 #2를 읽어 보니 대부분 #19에서 이미 구현되어 있었다. 실제 맡은 이슈는 #3이었다. 이슈 번호만 주면 AI가 그 이슈 안에서만 판단해, 다른 사람 코드와 이어지는 부분을 놓칠 수 있었다.
- 수정 프롬프트: "#3 이슈에 대한 코드 생성 작업을 진행할거야. 앞뒤 기능들과의 연계성이 끊어지지 않도록 제시해둔 입력과 출력 속성이나 형태를 그대로 반영해서 작업해줘"
- 수정 이유: 9명이 기능을 나눠 만들기 때문에, 함수 이름·입력·출력 형태가 하나라도 바뀌면 다른 팀원 화면이 깨진다.
- 검증:
  - AI가 구현 전에 이 함수를 쓰는 곳(`join.js`)과 다음 단계가 받는 형태를 먼저 찾아 정리했다.
  - #4에서는 이슈 본문의 출력(`origin_station`)과 이미 만들어진 코드(`origin_station_id`)가 다르다는 것을 발견해, 코드 쪽 이름에 맞추고 이슈 수정을 제안했다.
  - `npm test`(검사 6개·8개 추가) 통과, 가로 375px 화면 확인 → PR #34, #35 병합.
  - 같은 프롬프트를 전지원님도 #11·#12에 써서, 출력 형태 오류(buttonTitle 임의 추가)를 잡았다 → 팀 공통 프롬프트가 됨.

### [10/4] 문희원 개인 경로 화면 — 아직 없는 기능에 기대지 않게 (#13)
- 상황: 개인 경로 화면은 경로 계산(#25), 권장 출발 시각(#22), 장소 링크, 지하철 데이터에 기대는데, 작업 시점에는 모두 비어 있었다.
- 초안 프롬프트: (#3과 같은 형식) "#13 이슈에 대한 코드 생성 작업을 진행할거야. … 입력과 출력 속성이나 형태를 그대로 반영해서 작업해줘"
- 결과 / 문제: AI가 의존 기능을 표로 정리하면서 두 가지 문제를 먼저 알려줬다. ① 이슈 입력에 있는 `participant_id`가 공유 링크 규칙상 확정 정보에 들어가지 않는다. ② 의존 함수가 모두 미구현이라 그대로 부르면 화면이 멈춘다.
- 수정 프롬프트: "그대로 진행해줘" (AI가 제안한 방식 승인)
- 수정 이유: 각 함수의 모양(시그니처)은 그대로 부르되, 비어 있으면 대체 동작(확정 때 저장된 분 + '예상' 강조, 출발 시각 줄 숨김)을 하게 해서 다른 팀원 기능이 들어오면 고치지 않아도 실제 값이 보이도록 했다.
- 검증: 검사 15개 추가 통과, 375px 확인 → PR #36 병합. 이후 #22(권장 출발 시각)를 넣자 화면 수정 없이 출발 시각이 나타났다(PR #38).

### [10/5] 문희원 앱 사용 피드백 정리 — "별로인 부분이 있으면 먼저 알려줘"
- 상황: 심사용 사이트를 써 보고 팀에 피드백 5개를 남기려 했다.
- 초안 프롬프트: "조원들에게 피드백을 남기려고 하는데, 논리적이고 명확하게 작성해줘." + 피드백 원문 5개
- 결과 / 문제: 그대로 다듬기만 하면 사실과 다른 요청이 섞일 수 있었다(이미 있는 기능을 없다고 하거나, 다른 팀원이 일부러 바꾼 규칙을 되돌리자고 하는 등).
- 수정 프롬프트: "… 만약 별로인 부분이 있으면 내게 먼저 알려줘."
- 수정 이유: AI가 바로 고쳐 쓰기 전에 코드와 대조해 근거부터 확인하게 하려고.
- 검증:
  - AI가 코드를 확인해 세 가지를 짚었다. ④번(경로 먼저 보기)은 결과 화면에 경로 카드가 이미 있음(#53), ②번(검색)은 10/4에 일부러 바꾼 규칙(PR #66), ①번은 막차·첫차 시간을 고려해야 함.
  - "지금 / 제안" 형식으로 사실에 맞게 고쳐 기능 수정 요청서에 등록했다.
  - 이슈 #69~#78로 나뉘어 10/6까지 모두 반영됐다(새벽 시간 제외, 중간 글자 검색, 노선 색 경로선, 캐릭터 등).

### [10/6] 문희원 예시 닉네임·캐릭터 — 원하는 것과 아닌 것을 나눠 말하기 (#73)
- 상황: 예시 시나리오 닉네임을 캐릭터 이름으로 바꾸고, 9명까지 캐릭터를 구분해야 했다. 콘텐츠팀 그림이 아직 없어 AI가 임시 그림과 이름을 만들었다.
- 초안 프롬프트: "임시캐릭터 이름은 고치지 말아줘. 그냥 감이, 딜이, 택이만 남기자"
- 결과 / 문제: AI가 "임시 캐릭터를 쓰지 말자"로 이해해 임시 그림까지 지웠다.
- 수정 프롬프트: "그림은 너가 만든대로 일단 해줘. 이름만 바꾸지 말아달라는 거였어."
- 수정 이유: 유지할 것(그림)과 바꾸지 않을 것(이름)을 한 문장에 섞어 말해 뜻이 둘로 읽혔다. 무엇을 남기고 무엇을 빼는지 나눠 말하니 바로 맞게 고쳤다.
- 검증: 9명 입력 화면에서 캐릭터 9개가 모두 다른지 확인, 검사 303개 통과. 이후 콘텐츠팀 '모이자 친구들' 9명 그림이 오자 같은 틀로 바꿔 넣음 → PR #82 병합.

### [10/6~10/7] 문희원 기획안 PPT(P.13~19) — 사실 확인과 양식 지키기
- 상황: 내부 리뷰·크로스 피드백·바이브코딩 개발·앱 소개 페이지를 AI와 함께 작성했다.
- 초안 프롬프트: "ppt 13페이지 내용도 내가 일단 작성하기는 했는데, 가독성이 떨어지는것 같아. 그리고 내용도 정확한지 검증이 필요해."
- 결과 / 문제:
  - AI가 기능 수정 요청서·GitHub 이슈·코드와 대조하다가 날짜가 틀린 것을 찾았다. 실제 반영일은 이슈 종료 시각(한국 시간) 기준 10.06인데 10.04~05로 적혀 있었다.
  - 앱 소개 페이지는 AI가 보기 좋게 새 모양으로 바꾸다 보니, 템플릿 양식을 지켜야 한다는 발표 정책과 어긋났다.
- 수정 프롬프트: "발표정책상 … '앱소개, 주요화면캡쳐' 양식은 그대로 지켜야해. 그리고 이다음 페이지인 '주요화면 캡처' 슬라이드에서 … 핵심기능 7단계를 소개하는 식으로"
- 수정 이유: 꼭 지켜야 하는 조건(템플릿 양식)과 자유롭게 바꿔도 되는 부분(다음 장)을 나눠 알려줬다.
- 검증:
  - 슬라이드를 이미지로 뽑아 글자 넘침과 겹침을 확인했다.
  - 후보 역 25곳·장소 164곳, 새벽 1~5시 제외 등 숫자는 데이터 파일과 코드로 다시 확인했다.
  - "평균 + 표준편차" 표현이 맞는지는 `recommend.js`(`score: avg + std`)와 `CLAUDE.md`로 확인했다.
